# 07 — AI Engine: Providers, Cost Intelligence, Model Policies

**Status:** Phase 0 RFC
**Package:** `packages/ai/`
**Constitutional lock:** No AI Vendor Dependency — Adapters only

---

## 1. Responsibilities

| Module | Owns |
|---|---|
| Provider Registry | OpenAI, Claude, Gemini, OpenRouter, Ollama, LM Studio, vLLM, Azure, … |
| Adapters | Vendor SDK isolation |
| Router | Pick provider/model per task class |
| **Cost Intelligence** | Cheapest/fastest sufficient model; budgets; hard-stops |
| Prompt Templates | Versioned prompts |
| Prompt Evaluation | Rollback / light A-B |
| Retry / Fallback / Stream / Cache | Reliability & UX |

Meta does **not** own Cost Intelligence.

---

## 2. Adapter contract

```text
AIAdapter {
  id, vendor, capabilities: { chat, vision, embed, json_mode, tools }
  complete(req) → stream | message
  embed(req) → vectors
  health() → ok | degraded
}
```

Engines call `AIEngine.complete({ taskClass, messages, schema, budgetClass })` — never `openai.chat...`.

---

## 3. Cost Intelligence

### Per-task selection

Example: Gemini enough → skip GPT-class model. Prefer sufficient quality at lowest expected cost/latency.

### Budgets

- Track spend vs Config / Policy budgets (Global→Project)
- Hard-stop when exceeded → DomainError `POLICY_DENIED` / governor
- Surface spend in Observability + optional Inbox

### Inputs to routing

| Signal | Use |
|---|---|
| Task class | research_summarize, content_longform, validate_json, … |
| Quality tier | draft / final / critical |
| Latency class | interactive / batch |
| Policy caps | tokens, $/day, provider allowlist |
| Health | skip degraded providers |

---

## 4. Prompt system

```text
Prompt Template → Prompt Version → Prompt Evaluation
```

- Templates are provider-agnostic; adapters apply formatting tips
- Versions immutable; rollback by pointer
- Evaluation: light offline/online A-B; keep winner version
- All stored artifacts include `schema_version`

---

## 5. Reliability

| Concern | Behavior |
|---|---|
| Retry | Policy backoff; idempotency keys where needed |
| Fallback | Next provider in chain for task class |
| Stream | Token stream to Domain API; cancelable |
| Cache | Prompt+input hash for deterministic reuses (policy-gated) |
| One provider down | System remains usable |

---

## 6. Model policies (Feature + Policy)

Controllable surfaces:

- Priority order per task class
- Cost ceilings
- Fallback chains
- Max tokens
- Enable/disable experimental models
- Local-only mode (air-gapped preference)

Resolution honors Feature→Policy→Runtime (+ License later).

---

## 7. Interaction with Resource Scheduler

AI jobs compete for token/GPU/VRAM budgets under Automation Resource Scheduler + Governor. Cost Intelligence proposes; Governor admits.

---

## 8. Domain API (thin)

Most AI calls are **internal** from Content/Growth. UI may expose:

- `SettingsAPI` model preferences
- Provider key setup via Vault-backed Account/Settings
- Cost dashboards (read models)

No raw prompt playground required for V1 Mission Center; optional Tools panel later.

---

## 9. Secrets

API keys only in Vault / OS keychain. Config stores **refs**, never plaintext keys. See `12_INFRASTRUCTURE.md`.

## 12. V1 provider matrix (intent)

| Provider | Role |
|---|---|
| At least 1 cloud chat | Default generation |
| At least 1 fallback cloud | Resilience |
| Local (Ollama/LM Studio) | Optional offline / privacy |
| Embeddings | Knowledge/Memory search (opt) |

Exact defaults chosen at implementation; registry must allow swap without engine rewrites.

---

## 13. Anti-patterns

1. `import OpenAI from 'openai'` inside Content Engine
2. Hard-coded model names in Growth Decision
3. Meta owning spend routing
4. Silent spend past Policy budget
5. Prompt strings scattered without versioning
